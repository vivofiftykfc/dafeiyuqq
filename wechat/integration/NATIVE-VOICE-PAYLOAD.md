# 原生语音载荷准备（2026-10-23）

当前状态：本机中文女声音色合成、Tencent SILK 编码、结构/时长/解码核验已接入 `/tts`。微信原生语音气泡发送仍未接通。`payload_ready` 只说明载荷准备成功，所有结果仍带 `native_transport_connected=false`、`wechat_sent=false`。

音色、模型、运行环境与音频仍位于 `__VOICE_ROOT__`，当前小鲸鱼使用 Kokoro `zf_001`，语速 1.03。角色由原有 `/media` 来源及角色版本校验绑定，未改变角色选择、聊天记录或权限。此功能不录麦克风、不播放到系统扬声器、不改默认输入设备，也不调用微信进程。

新增 `native_voice_payload.py`：只接受该目录下 private 的 WAV；原生候选限60秒；校验 Tencent 头、每个长度字段及完整包边界；编码后实际解码，核对20毫秒包数、实际时长、原文件哈希；输出不可覆盖的 SILK 和同名 `.voice.json`。重用时核对音色、角色、目标、包数、时长和哈希，冲突拒绝。目标绑定主人私聊。

编码器修复：原先不足一个20毫秒包的尾部可能被截掉，现在对最后一个包补零；补充重采样 flush 的时长检查；已有 SILK 不覆盖；临时 PCM/编码文件使用独立名称并回收。准备失败不把普通本地 WAV 的生成说成失败或已发出。超过60秒时保留本地音频，明确尚未准备原生载荷。

真实本地诊断：生成“我在呢，慢慢说，不着急。”，WAV约2.228秒，112个包、2240毫秒，编码/解码通过。SenseVoice 从产生的 SILK 转写为“我在呢慢慢说，不着急。”。这证明一次本地语音内容可解码，不是真实微信收发验收，也不能证明长期语音质量。

证据：`runtime/native-voice-payload-actual.json`、`runtime/native-voice-payload-asr.json`；12项角色/存储/入站/载荷测试；合成及载荷实际通过运行中的媒体 API。

- [pywechatcc](https://github.com/CcNicklause/pywechatcc) 的发送实现读取当前聊天窗口、播放音频并操控录音按钮，默认查找窗口/音频路由不符合此项目的主号隔离要求，未直接运行。
- `tools/inspect-voice-native.py` 仅分析本机指纹锁定的 DLL 文件，保存调用点与反汇编线索；未访问运行中进程、未尝试未验证函数。包括 UI 统计构造、上传流程、XML解析等候选，不能当成已找到可调用的发送接口。
