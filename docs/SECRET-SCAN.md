# 发布前的密钥检查

发布流程同时检查当前源码与Git历史，不能通过“删除配置文件再提交”来掩盖历史泄漏。账号配置、环境凭据、聊天、模型和运行环境不进入源码归档。

本次在本机解析相关连接配置和凭据文件，仅在内存中提取真实密钥值，检查源码及所有Git对象中是否出现；密钥本身没有打印或写入审计报告。结果为未发现匹配。另用Gitleaks 8.30.1对完整提交历史执行脱敏扫描。

Gitleaks报告中的已复核项来自抖音SDK公开的客户端应用标识、PEM头尾解析代码及模型tokens文件的SHA-256，不是维护者的API Key。`.gitleaksignore` 仅记录这些具体提交/文件/规则/行号的指纹，没有整目录忽略。新提交或位置变化仍会重新检查；不要把实际密钥加入忽略清单。

CI只使用GitHub为该次工作流提供的临时访问令牌下载公开检查工具，不需要维护者的模型API Key。检查工具下载后先核对官方SHA-256，扫描时使用100%脱敏输出。

任何扫描都不能替代对发布范围的控制。新增第三方代码、示例、截图或配置时仍应人工检查；若未来误传凭据，先轮换，再清理Git历史和发布资产。
