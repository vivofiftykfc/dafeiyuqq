# 迁移与备份

## 换目录前

先保存配置与任务状态，关闭自主回复/发布；让微信原生桥接正常卸载，再停止项目后台。保留应用客户端，避免用进程名批量结束所有node/python。

复制源码、自己的配置、记忆和素材到新位置。不要把整个Python虚拟环境视为可自由搬动：Windows venv的启动器、`.pth`、缓存和目录链接可能包含旧绝对路径。新电脑应从依赖声明重建环境；同电脑迁移可暂留兼容目录链接，随后逐项改成新路径。

## 本机目录整理策略

```text
项目根目录/
├─ wechat/                  # 原桌面微信工程的实际内容
├─ local/diary-desktop/      # 原桌面日记副本
├─ docs/architecture-local/  # 原桌面架构图、源文件和历史版本
└─ local/migration/          # 仅本机迁移日志与核验记录
```

这些目录中的私人数据与历史报告不应直接公开。需要展示的架构图应重新生成不含账号、联系人和本机路径的版本。

## 验证与回退

1. 正常停止后补齐最终差异，比较文件数量/长度，并对集成代码与重要配置核对哈希。
2. 检查目录链接的真实目标；不能只复制链接本身。
3. 修正启动器、配置、工作区和日记同步路径。
4. 启动普通后台，再启动管理员原生桥接；检查端口、账号身份、健康接口和真实收发。
5. 保留旧目录的回退备份，确认功能通过后再安排清理。回退时先停新服务，再切回旧目录，不能让两个副本同时写入同一账号历史。

运行中的SQLite需要备份API或正常停止后的完整副本。GitHub源码包不是个人数据备份，也不包含模型、账号授权和显卡驱动。
